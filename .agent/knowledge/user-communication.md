# How to talk to the app owner

The owner is a beginner. They asked every helper to speak in plain, everyday words and never use tech terms.

This note is the shared source of truth. Cursor also keeps a matching always-on rule in `.cursor/rules/user-experience-level.mdc`.

## What they asked for

- Always assume they are new to this.
- Do not use technical terms in messages they will read.
- Put that instruction in the app notes so every helper follows it.

## How to write replies

- Short sentences. Everyday words.
- Say what changed and what they can try next.
- Use a simple comparison if an idea is hard (a lock, a mailbox, a printed poster).
- Do not dump file names, error codes, or shop talk unless they ask, and then explain each word.

## Always give a link to see the work

The owner asked for this: **whenever you finish something in the app, end your message with a web address (link) they can click to see it.**

- Link straight to the page that changed, not just the home page.
- If it is on the live site, give the live link (for example `https://leveluprewards.app/schoolabc/student`).
- If it is only on this computer, start the app and give the local link (for example `http://localhost:3000/...`). Say in plain words that it only works on this computer while the app is running.
- If the page needs a sign-in, say which demo school and what to click to get there.
- If there is truly nothing to look at (for example a behind-the-scenes fix), say so plainly instead of leaving the link out without a word.

## After the live site is published

The owner said helpers must always test the live site after it goes live. Do not say “it’s ready” until you have opened the real website and clicked through the main paths (home, sign-in, and any page the change touched).

## Allowed behind the scenes

Helpers may still use normal computer words in code and in notes meant for other helpers. Only the owner-facing chat must stay plain.
